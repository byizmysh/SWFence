# Architecture

- `swfence` owns one UCI package, two nftables includes and isolated dnsmasq/uhttpd instances under procd.
- `inet fw4` prerouting priority -310 drops nonlocal destinations before standard conntrack/redirect hooks. Its later NAT chain redirects selected console DNS/HTTP requests to ports 5357/18087.
- A dedicated `bridge swfence` table also filters same-LAN console frames. Its include recreates only that table on firewall reload. The default policy for other MACs is unchanged.
- Allowed destinations return to existing router processing; they do not bypass other firewall policies. IPv6 is dropped for matching source MACs.
- MACs, RFC1918 addresses and ports are validated before generation. Configuration is data, never sourced/evaluated as shell code.
- Applying snapshots managed files, checks the whole fw4 ruleset, reloads it atomically, and records the applied configuration only after success. A detected failure restores files and attempts a previous-rules reload. A separate configuration layer restores the prior UCI file if apply fails.
- Saved versus applied settings are compared explicitly. Presence checks are not a semantic attestation of every kernel rule. Native offload flowtables are regenerated by fw4; nonstandard hardware acceleration requires device testing.
- A procd collector accumulates sampled per-path drop totals in RAM every 5 seconds, independent of LuCI. Samples share a lock and atomic state file with status requests. A new router-local calendar day starts a new baseline without altering firewall rules. Daily totals survive local service restarts; router reboots clear them. The panel displays the router date/timezone and actual collection start. See testing.md for sampling limitations.
- The LuCI view uses JSONMap and three named RPC methods: status, diagnostics, configure. rpcd ACL grants no arbitrary shell/file/UCI API access. Configuration strings are bounded, control characters are rejected, and only fixed UCI paths are written. Methods run within the authenticated LuCI/rpcd authorization model; there is no separate public HTTP admin service.
- The CGI endpoint exposes a fixed response only for fixed connection-check hosts, method GET and path `/`. It does not proxy traffic, accept uploads, or serve arbitrary application files.
- The diagnostic network targets come only from the last validated applied router address. Checks never probe external servers. A separate optional exception worker resolves only explicitly configured applied domains through normal router DNS; see internet-exceptions.md. Local diagnostics cannot establish console-to-WAN isolation.
- `SWFENCE_ROOT` prefixes filesystem paths for development tests. Public RPC methods do not accept environment or filesystem-path parameters.
